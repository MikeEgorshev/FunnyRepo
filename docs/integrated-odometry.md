# Интегрированная резервная одометрия

> **Экспериментальный режим, в сдачу не входит.** Жюри запускает штатный `ros2 launch tram_odometry tram_odometry.launch.py` — см. [docs/solution.md](solution.md), раздел 2.

Отдельный режим `integrated_odometry_node` объединяет событийный EKF Mike
с причинной моделью исполнительного механизма, мягкой коррекцией доверия
к колёсам и ограниченной адаптацией эффективной тяги по идеям Gemini.
Существующий `tram_odometry_node` сохранён для сравнения.

## Запуск

```bash
colcon build --packages-select tram_vehicle_msgs tram_odometry
source install/setup.bash
export ROS_DOMAIN_ID=12 ROS_LOCALHOST_ONLY=1
ros2 launch tram_odometry integrated.launch.py use_sim_time:=true
```

В другом терминале с теми же ROS_DOMAIN_ID и ROS_LOCALHOST_ONLY:

```bash
source install/setup.bash
ros2 bag play /path/to/30618_88aea4d9 --clock
```

Для живого транспорта оставить `use_sim_time:=false`. Выходы, типы, единицы
и названия фреймов совпадают с существующим пакетом. Новых runtime-зависимостей нет.
ROS Humble/colcon/DDS должны быть проверены в целевом окружении: на Windows
разработка проверялась через pytest и последовательное воспроизведение callbacks.

## Защита входов

GNSS задаёт начальную привязку в окне `init_window_s` (по умолчанию 5 с).
Окно не открывается повторно при позднем сообщении со старой меткой. После окна
`gnss_corrections=true` включает отдельный корректор положения. Это соответствует
предоставленным уточнениям организаторов от 26–27 сентября: редкие фиксы
разрешены для коррекции пути и выбора тупика без снижения оценки.
`primary_sync` принудительно выключен; подписка на эталон отсутствует.
При отсутствии GNSS выдаётся относительная одометрия в `odom`.
Launch сохраняет прежний автономный режим по умолчанию: проверочный bag пока
не показал выигрыша корректора. Для включения добавить `gnss_corrections:=true`.
При прямом запуске executable действует существующий параметр из конфигурации.

Корректор меняет только позиционную привязку и частную копию выбора ветви карты.
Состояние EKF, его ковариация, масштаб колёс, тяга и выходная скорость не меняются.
GNSS velocity не используется. Проверяются статус фикса в ноде, конечность чисел,
возрастание меток, близость к времени фильтра (±2 с), расстояние до карты и
предсказанного положения. Нужны два согласованных фикса не дальше 30 с друг от друга;
изолированный редкий фикс консервативно пропускается. Пороговые расстояния и частота
берутся из существующих `gnss_*` параметров. На прежней ветви применяется скалярная
коррекция с дисперсией GNSS и шумом пути `sigma_u`; ветвь переключается дискретно.
Направление движения по отводу и ориентация корпуса хранятся отдельно.
После исчезновения GNSS положение продолжается по интегралу модели без скачков
привязки EKF к остановкам. Ошибочная ветвь без новых различающих данных не исправляется.

Для автономного сравнения:

```bash
ros2 launch tram_odometry integrated.launch.py use_sim_time:=true gnss_corrections:=false
```

Колёса переводятся из км/ч в м/с; каждое измерение учитывается один раз.
Дубликаты и перестановки в одном канале не переиспользуются. Выбросы, зависание
и юз проверяются исходной диагностикой. Умеренная невязка дополнительно уменьшает
доверие к измерению. Остановка требует свежих нулевых показаний обеих тележек,
отсутствия признаков юза и тяги. Уклон не сбрасывается в ноль при остановке.

## Модель

Таблица Mike содержит результирующее ускорение, поэтому сопротивление Davis
не вычитается повторно. Команда сглаживается апериодическим звеном с tau=0.2 с
после табличной задержки; запросы прошлых времён не зависят от будущих команд.
Эти значения требуют независимой идентификации на train, а не подбора по checker.

Коэффициент тяги ограничен 0.8–1.2 и изменяется медленно на исправных,
согласованных колёсах. Ускорение берётся из последовательных измерений,
а не из обнулённой разности `v_est-v_prev` после EKF update. Этот коэффициент
не является доказанной оценкой массы. Его выигрыш на известном bag мал;
для обобщения нужны независимые заезды.

Скорость соответствует опубликованной метке: специальная задержка 40 мс,
ранее выбранная по проверочному bag, в этом режиме отключена.

## Координаты и карта

Применяется непрерывный UTM 37N с вычитанием (300000, 6100000), без modulo.
Пример организатора покрыт тестом. Карта в репозитории описывает антенну master;
к её точке применяется жёсткий TF master→base_link: +9.873 м по оси корпуса,
−3 м по вертикали, в приближении нулевых крена и тангажа. Высота берётся из
существующей карты; геоидная поправка не вводится без подтверждения датума.
Если впоследствии карта заменяется картой base_link/головки рельса, этот TF
нужно изменить, иначе он будет учтён дважды. База антенн 12.436 м;
база тележек 7.55 м не используется для выдуманного измерения поворота.

При нескольких подходящих остановках абсолютная привязка не выполняется.
Остановка около развилки не переключает безусловно положение в тупик:
сохраняются альтернативные ветви и увеличивается неопределённость XY.
Это консервативное представление неоднозначности, не полноценный вероятностный
маршрутизатор. Без сигнала стрелки/других разрешённых различающих признаков
одни колёсные скорости могут не определить фактическую ветвь.

## Пропуски и время

Callback-публикации дополнены heartbeat через 40–60 мс. При `use_sim_time=true`
его метки следуют ROS-clock; пауза bag не создаёт будущих результатов.
Прогноз хранится отдельно и не изменяет основное состояние/историю измерений.
После двух секунд полного молчания входов прогноз сохраняет скорость вместо
бесконечного выполнения старой тяговой команды; ковариация продолжает расти.
Публикация не прекращается. Без новых измерений точность не гарантируется.
Память диагностических времён ограничена 500 последними значениями.

## Проверка

```bash
PYTHONPATH=src/tram_odometry python3 -m pytest src/tram_odometry/test -q
```

Тесты проверяют неизменность состояния скорости при позднем GNSS/эталоне, причинность
модели, дубликаты, 60-секундный прогноз и восстановление без двойного
интегрирования, TF, координаты организатора, остановку, ограничение адаптации,
паузу ROS-clock, симметрию ковариации и отсутствие подписки на эталон.
Добавлены проверки коррекции положения, выбросов/дубликатов, пропадания GNSS,
выбора отвода по двум фиксам, реверса с сохранением ориентации корпуса и подписки GNSS.
Тесты ноды используют doubles ROS API и не заменяют запуск DDS.

Известное ограничение: на `30618_88aea4d9` коррекции пока не дают общего выигрыша:
в воспроизведении callbacks 3D RMSE составляет 6.27 м против 5.85 м без коррекций,
конечная ошибка — 50.66 м против 48.09 м. Скорость совпадает побитово во всём
прогоне (RMSE 0.034453 м/с). Приняты 43 позиционные коррекции. Это исследовательский
режим, не доказанное улучшение для сдачи. Замена всех карт на версию Gemini в исходном фильтре Mike
снижала конечную ошибку до 8.43 м, но ухудшала общий RMSE до 6.77 м.
Поэтому карта не заменена по одному известному проверочному прогону.
Нельзя утверждать, что интеграция уже лучше обоих решений по всем метрикам.

Перед допуском: отдельные train/validation, настройка только на train,
проверка альтернатив карты, настоящий checker с ApproximateTimeSynchronizer,
измерение задержки вход→публикация, CPU/RAM и офлайн-сборка colcon.
