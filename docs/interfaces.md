# Интерфейсы решения

Контракт между частями решения и с судьёй организаторов. Статус — **предложение, утверждает лид**. Менять только отдельным PR `feat(interfaces): …` (AGENTS.md §7). Источники: README датасета, PDF задачи и разбор данных в [data.md](data.md). Пункты с пометкой «?» ждут ответа организаторов на QA-сессии.

## Входы ноды

| Топик | Тип | Частота | Смысл и единицы |
|---|---|---|---|
| `/vehicle/front_bogie_velocity` | `tram_vehicle_msgs/msg/VelocitySensor` | 10 Гц | `velocity` — скорость передней тележки, **км/ч** (так в данных, вопреки README); `frame_id: base_link` |
| `/vehicle/rear_bogie_velocity` | `tram_vehicle_msgs/msg/VelocitySensor` | 10 Гц | то же для задней тележки |
| `/vehicle/driver_position_cmd` | `tram_vehicle_msgs/msg/DriverControllerCommand` | 20 Гц | `position` (int8): 0 — нейтраль, +1…+15 — тяга, −1…−15 — торможение |
| `/sensing/gnss/master/fix` | `sensor_msgs/msg/NavSatFix` | 10 Гц | **только начальная выставка** в первые секунды прогона; после инициализации нода топик игнорирует |

Остальные GNSS-топики нода не читает. GNSS нужен только для офлайн-калибровки и метрик. Использовать GNSS, IMU, лидар или камеры в основном контуре — дисквалификация.

QoS подписок — best effort, `depth: 10`: совместимо с издателем `ros2 bag play` (reliable). Входы приходят с пропусками и пачками, поэтому нода обязана это переживать: см. [data.md](data.md).

## Выходы (их слушает судья)

| Топик | Тип | Частота | Содержимое |
|---|---|---|---|
| `/result/velocity` | `tram_vehicle_msgs/msg/VelocitySensor` | ≥ 20 Гц | `velocity` — оценка продольной скорости, **м/с** (?); `frame_id: base_link` |
| `/result/position` | `nav_msgs/msg/Odometry` | ≥ 20 Гц | `pose.pose.position` — x, y, z в локальной метрической системе эталона (?); `pose.pose.orientation` — курс по касательной к карте линии; `twist.twist.linear.x` — продольная скорость, м/с; ковариации заполнены; `header.frame_id: map`, `child_frame_id: base_link` |
| `/result/diagnostics` | `diagnostic_msgs/msg/DiagnosticArray` | 2 Гц | наш топик, судья его не читает: флаг проскальзывания, пропуски входов, доверие к одометрии, оценка масштаба колёс |

Правила публикации:

- Публикуем на **каждое входное сообщение** (тележки и контроллер — около 40 Гц в сумме), а не по таймеру.
- `header.stamp` выхода = `header.stamp` входа, который вызвал обновление. Не стенные часы: судья сопоставляет выход с эталоном по ближайшей метке с допуском около 0,05 с.
- Метки выхода не убывают. Входное сообщение со старой меткой (пачки, перестановки) учитываем в состоянии, но выход по нему не публикуем.
- Только онлайн-публикация во время проигрывания bag. Никакой постобработки «одним куском» в конце.

## Системы координат

- `map` — локальная метрическая система эталона: x — восток, y — север, z — вверх, метры (ENU). **Начало координат — открытый вопрос (?).** Рабочая гипотеза: первая точка `/sensing/gnss/master/fix` в прогоне, высота относительно неё же. Пересчёт WGS-84 → ENU делается в одной функции, её легко поменять после ответа.
- `base_link` — кузов трамвая, ось x — по ходу движения.
- Внутреннее состояние фильтра одномерное: `s` — дистанция вдоль маршрута (м) и `v` — скорость (м/с). Координаты x, y, z получаются только проекцией `s` на карту линии.

## Параметры ноды (`config/tram_odometry.yaml`)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `wheel_kmh_per_mps` | 3.5966 | делитель «км/ч по тележке → м/с»; калибруется по данным (см. [data.md](data.md)) |
| `vehicle_id` | `""` | если задан (`30618`/`30639`) — берём коэффициент конкретного трамвая |
| `route_map_file` | `maps/route.csv` | карта линии: столбцы `s_m, lat, lon, alt` |
| `model_params_file` | `config/model.yaml` | параметры тяги, торможения и сопротивления |
| `gnss_init_timeout_s` | 5.0 | сколько секунд ждём GNSS для выставки; нет GNSS — старт с начала карты или с `initial_s` |
| `initial_s` | `-1` | ручная стартовая дистанция по карте; `-1` — не задана |
| пороги проскальзывания, шумы фильтра | см. файл | описаны в `config/tram_odometry.yaml` |

## Внутренние модули (чтобы работать параллельно)

Пакет `tram_odometry` (ament_python). Логика — чистые функции и классы без ROS, их тестируют офлайн на bag через `research/`.

| Модуль | Интерфейс | Кто пишет |
|---|---|---|
| `model.py` | `accel(cmd:int, v:float, p:Params) -> float` — модельное ускорение, м/с² | задача «модель тяги» |
| `route_map.py` | `RouteMap.load(path)`, `.locate(lat, lon) -> s`, `.pose(s) -> (x, y, z, yaw)`, `.length` | задача «карта линии» |
| `estimator.py` | `Estimator.predict(t, cmd)`, `.update_wheels(t, front_kmh, rear_kmh)`, `.state() -> (s, v, cov, flags)` | задача «фильтр» |
| `node.py` | только ROS: подписки, публикации, параметры; без математики | задача «каркас пакета» |
