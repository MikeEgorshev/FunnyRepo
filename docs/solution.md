# Решение: резервная одометрия трамвая по модели (ветка `claude/odometry-core`)

Описание по полям формы сдачи ([форма](context/2026-09-25-submission-form.md) — в PR #1). Цифры быстродействия — замер в чистом ROS 2 Humble с лимитами жюри. Точность на реальных прогонах в этой ветке **не измерена**: датасет в среде разработки недоступен. Весь путь от прогонов к карте, подобранной модели и метрикам — одна команда (`scripts/pipeline.py`); она проверена на синтетическом датасете в формате организаторов, ниже — эти цифры. Презентация для жюри — [`docs/presentation.html`](presentation.html), пересобирается по результатам конвейера (`scripts/make_report.py`).

## 1. Код

Пакет `src/tram_odometry` (ament_python, чистый Python, внешних зависимостей нет): нода `tram_odometry_node` подписывается на `/vehicle/*` и GNSS (только выставка) и публикует `/result/velocity`, `/result/position`, `/result/diagnostics`.

Офлайн-модули того же пакета: `mapping.py` — карта линии и места стоянок по GNSS обучающих прогонов, `identify.py` — подбор параметров модели по прогонам. Их вызывают скрипты в `scripts/`; нода их не использует.

Для сборки в рабочем пространстве нужен пакет сообщений организаторов `tram_vehicle_msgs` (`VelocitySensor`: header + `float64 velocity`; `DriverControllerCommand`: header + `int8 position`). В этой ветке его нет: `*_msgs` кладёт лид (AGENTS.md §6). Карта линии и места стоянок — файлы CSV, задаются параметрами.

## 2. Инструкция для жюри

### Сборка

```bash
source /opt/ros/humble/setup.bash
colcon build              # без интернета: зависимости только из ROS 2 base
source install/setup.bash
```

### Запуск на rosbag

```bash
ros2 launch tram_odometry tram_odometry.launch.py params_file:=<свой YAML>   # терминал 1
ros2 bag play <каталог прогона>                                              # терминал 2
```

Готовый YAML с картой, стоянками, подобранной моделью и `filter.k0` пишет конвейер: `results/fitted.yaml` (см. «Логи, метрики, задержка»). Вручную — по образцу `config/tram_odometry.yaml`: `route_map_file` (карта: `s_m, lat, lon, alt`), `stops_file` (места стоянок: `s_m, sigma_m`), `filter.k0` — масштаб колёс (30618 — 3,5953, 30639 — 3,6106, по умолчанию 3,5966).

### Что ждать на выходе

| Топик | Тип | Содержимое |
|---|---|---|
| `/result/velocity` | `tram_vehicle_msgs/VelocitySensor` | продольная скорость, м/с; `frame_id: base_link` |
| `/result/position` | `nav_msgs/Odometry` | `base_link` в сетке MGRS судьи (UTM 37N минус 300 000 / 6 100 000); курс; скорость; ковариации. `frame_id: map`; без GNSS на старте — `odom`, x = путь от старта |
| `/result/diagnostics` | `diagnostic_msgs/DiagnosticArray` | проскальзывание, отношение скольжения, доля сцепления, расхождение и зависание тележек, масштаб колёс k, σ положения, число привязок к стоянкам |

Выход публикуется по таймеру 25 Гц. Метка — метка последнего входа плюс прошедшее время (не дальше 0,2 с), метки не убывают. Между входами прогноз по ускорению колёс; если колёса молчат — по модели. `/result/position` публикуется, только когда положение определено (есть точка старта и курс или выставка закончена): до первого фикса выход (0, 0) испортил бы метрику судьи.

### Логи, метрики, задержка

- `scripts/check_ros.sh` — сборка без сети в `ros:humble-ros-base` с лимитами 2 ядра и 512 МБ, `colcon test` и замер реального времени (`REALTIME_ARGS="--stall-at 30 --stall-s 1.5"` глушит все входы).
- `scripts/realtime_check.py` — синтетические входы с реальной частотой: задержка, частота, разрывы выхода, CPU и память ноды; `--gnss LAT,LON` проверяет выставку.
- `scripts/pipeline.py --dataset <dataset>/data --out-dir results/` — всё одной командой (pip-пакеты `rosbags`, `pyyaml`): прогоны делятся на обучающие и проверочные по хешу имени; по обучающим — карта и стоянки (`build_route_map.py`), модель и k0 (`fit_model.py`); на проверочных — метрики судьи для нашей ноды, модели по умолчанию, варианта без карты и сырой одометрии, плюс ошибка модели за 20 с без колёс. Пишет `route.csv`, `stops.csv`, `fitted.yaml`, `results.json`.
- `scripts/make_report.py --results results/results.json` — вшивает результаты в `docs/presentation.html`.
- `scripts/evaluate_bags.py <прогоны…> --route-map … --stops … --params fitted.yaml` — точность по bag без ROS тем же кодом, что в ноде.
- `scripts/make_synthetic_bags.py --out-dir /tmp/synth` — синтетический датасет в формате организаторов (петли, уклоны, остановки, буксование, юз, пропуски, зависание) для проверки конвейера.

## 3. Математическая модель

### Модель тяги и торможения (на единицу массы, масса неизвестна)

```
a = f_tr(u, v) − f_br(u, v) − r(v) − g·θ(s) + d
du/dt = (n − u) / τ                                      сила привода отстаёт от ручки

f_tr = (u/15)·min(a_max, a_max·v_base / v),   u > 0     постоянная сила, затем постоянная мощность
f_br = (|u|/15)·b_max·blend(v),               u < 0     blend(v) = φ + (1 − φ)·min(1, v / v_blend)
r(v) = (A + B·v + C·v²)·min(1, v / v_stop)               сопротивление, у остановки плавно к нулю
θ(s) — уклон по высоте карты (база ±10 м)
```

`n` — позиция контроллера −15…15, `u` — она же после запаздывания привода τ, `v` — скорость, м/с. В YAML по умолчанию — стартовые оценки (τ = 0). Настоящие параметры подбирает `fit_model.py` (`identify.py`): на чистых участках (тележки согласны) ускорение колёс плюс g·θ по карте; при известных τ, v_base и v_blend модель линейна по остальным параметрам, поэтому три нелинейных перебираются по сетке, остальные — МНК, сопротивление — по выбегу. На синтетике с известной истиной τ восстанавливается точно, a_max и b_max — с ошибкой < 1 %.

### Фильтр вдоль пути (EKF)

Состояние `[s, v, d, k]`: дистанция вдоль пути, м; скорость, м/с; возмущающее ускорение, м/с² (масса, ошибка модели); масштаб колёс, (км/ч тележки)/(м/с).

- **Прогноз** с шагом 0,05 с: `s += v·h + a·h²/2`, `v = max(0, v + a·h)`; `d`, `k` — случайные блуждания. Якобиан по скорости — численно.
- **Измерение** — скорость тележки в км/ч: `h(x) = k·v`, `H = [0, k, 0, 0]`. По колёсам k и v неразделимы, поэтому в этом обновлении k считается известным.
- **Масштаб k** уточняется по привязкам к стоянкам: `k_изм = k · (путь по одометрии) / (расстояние между стоянками по карте)`, при расстоянии ≥ 200 м, не дальше 3 % от k0. Неопределённость k входит в σ_s членом `(σ_k/k · путь после привязки)²`.
- **Стоянка**: обе тележки < 0,1 м/с, нет тяги и оценка < 1 м/с → измерение v = 0. При большей оценке нули колёс — юз, а не стоянка.

### Проскальзывание и отказы датчиков

| Признак | Правило | Действие |
|---|---|---|
| Фаза движения | тележки согласны в пределах 0,1 м/с — среднее; иначе тяга — медленная, торможение — быстрая, выбег — среднее. Отсчёты приводятся к одному моменту по ускорению каждой тележки | выбор скорости для фильтра |
| Расхождение тележек | `|v_f − v_r| > max(0,3 м/с; 3 % v)` два отсчёта подряд | флаг |
| Ускорение колёс | > 2,0 м/с² в тяге, < −3,0 м/с² в торможении (база 0,3 с) | тележка исключается |
| Согласие тележек | обе свежие, без флагов, расходятся ≤ 0,15 м/с или 1,5 % | отсчёт принимается без χ²-отсева: на настоящих данных трамвай тормозит и при ручке в нейтрали, модель этого не видит |
| Невязка | χ² > 9 (3σ) — если тележки не согласны или одна; флаг после 3 отсечений подряд | отсчёт отбрасывается; дольше 6 с — принимается с большим шумом |
| Стоянка | v = 0 по колёсам | возмущение d сбрасывается: торможение не переходит в следующий разгон |
| Опоздавший отсчёт | старее текущего времени фильтра на 0,25–10 с (в начале прогона тележка бывает на 1,1 с позади) | отбрасывается; скачок назад больше 10 с — новый прогон |
| Зависание | 6 одинаковых ненулевых показаний подряд | тележка исключается до смены показания |
| Пропуск | нет свежих данных > 0,3 с | только модель, ковариация растёт |
| Мусор | NaN, ∞ | отбрасывается |

### Положение

- **Выставка** в окне 5 с: точка старта — медиана фиксов master, если трамвай стоит (одиночный прыжок > 10 м отбрасывается), иначе последний фикс. Курс — по базе антенн master → rover (обе на оси трамвая, 12,436 м): работает и на месте; без rover — по смещению.
- **С картой**: в конце окна s ставится проекцией точки старта на карту с учётом направления (двухпутные участки); дальше координаты, уклон и места стоянок — с карты. **Без карты** — прямая от точки старта. **Без GNSS** — относительная одометрия, `frame_id: odom`.
- **Привязка к стоянке**: стоим > 5 с и ровно одно место стоянки в гейте `3·√(σ_s² + σ_ст²)` (не уже 5 м и не шире 80 м) — поправка s; две стоянки в гейте или ни одной (светофор) — поправки нет.
- **Выходная точка** `base_link` = антенна master + 9,873 м вперёд по пути, высота −3,0 м (tf от организаторов).
- **Старт вдали от карты** (депо, отвод, дальше 50 м) — карта не используется, выход по прямой от старта.
- **Коррекция по GNSS** (`gnss_corrections`, по умолчанию выключена): фикс master после выставки проецируется на карту и уходит в фильтр привязкой дистанции (σ 2 м). В проверочном прогоне организаторов GNSS есть всплесками раз в 2–3 минуты. Описание задачи разрешает GNSS «для начальной выставки и коррекции», README датасета — только для выставки; включать ли — решение команды.

## 6. Ограничения и план

### Ограничения

- **Проверено на одном настоящем прогоне** (из пакета судьи); на 122 прогонах датасета — нет, модель по ним не подобрана: датасета в среде разработки не было. Конвейер для этого готов.
- **Карта в ветку не входит**: карта по настоящим данным есть в ветке #4 (`src/tram_odometry/maps/route.csv`, `route_stops.csv`); без карты положение на этой линии не годится.
- **Юз дольше 6 с** на обеих тележках сдвигает оценку: после 6 с фильтр снова принимает колёса (с большим шумом), иначе ошибка модели накапливалась бы без предела.
- **Нет отводов у конечных**: у конечной трамвай уходит на съезд, путь по карте длиннее — до 20 м ошибки на проверочном прогоне.
- **Карта и места стоянок** в ветку не входят: их строит конвейер по GNSS обучающих прогонов. Карта — один замкнутый круг.
- Эталон в оценке — антенны GNSS, у судьи — слияние с лидаром.
- Сообщения `tram_vehicle_msgs` проверены по заменителю с теми же полями.

### План

1. Запустить `pipeline.py` на 122 прогонах; при нелинейности по позициям — табличная характеристика привода вместо двух параметров.
2. Отводы и депо на карте: граф путей вместо одного круга.
3. Подобрать шумы и пороги по результатам: сначала масштаб колёс и гейт стоянок, потом детекторы проскальзывания и длительность езды на модели при юзе.
4. Определять номер трамвая по данным: масштаб колёс и отклик на позиции контроллера различаются.
