# Решение: резервная одометрия трамвая по модели (ветка `claude/odometry-core`)

Описание по полям формы сдачи ([форма](context/2026-09-25-submission-form.md) — в PR #1). Цифры быстродействия — замер в чистом ROS 2 Humble с лимитами жюри. Точность на реальных прогонах в этой ветке **не измерена**: датасет в среде разработки недоступен. Ниже — результаты на синтетике и команда, которой точность меряется на данных.

## 1. Код

Пакет `src/tram_odometry` (ament_python, чистый Python, внешних зависимостей нет): нода `tram_odometry_node` подписывается на `/vehicle/*` и GNSS (только выставка) и публикует `/result/velocity`, `/result/position`, `/result/diagnostics`.

Для сборки в рабочем пространстве нужен пакет сообщений организаторов `tram_vehicle_msgs` (`VelocitySensor`: header + `float64 velocity`; `DriverControllerCommand`: header + `int8 position`). В этой ветке его нет: `*_msgs` кладёт лид (AGENTS.md §6). Карта линии и места стоянок — файлы CSV, задаются параметрами.

## 2. Инструкция для жюри

### Сборка

```bash
source /opt/ros/humble/setup.bash
colcon build              # без интернета: зависимости только из ROS 2 base
source install/setup.bash
```

### Запуск на rosbag

```bash
ros2 launch tram_odometry tram_odometry.launch.py params_file:=<свой YAML>   # терминал 1
ros2 bag play <каталог прогона>                                              # терминал 2
```

В YAML (образец — `config/tram_odometry.yaml`) задаются `route_map_file` (карта: `s_m, lat, lon, alt`), `stops_file` (места стоянок: `s_m, sigma_m`) и `filter.k0` — масштаб колёс трамвая (30618 — 3,5953, 30639 — 3,6106, по умолчанию 3,5966).

### Что ждать на выходе

| Топик | Тип | Содержимое |
|---|---|---|
| `/result/velocity` | `tram_vehicle_msgs/VelocitySensor` | продольная скорость, м/с; `frame_id: base_link` |
| `/result/position` | `nav_msgs/Odometry` | `base_link` в сетке MGRS судьи (UTM 37N минус 300 000 / 6 100 000); курс; скорость; ковариации. `frame_id: map`; без GNSS на старте — `odom`, x = путь от старта |
| `/result/diagnostics` | `diagnostic_msgs/DiagnosticArray` | проскальзывание, отношение скольжения, доля сцепления, расхождение и зависание тележек, масштаб колёс k, σ положения, число привязок к стоянкам |

Выход публикуется по таймеру 25 Гц. Метка — метка последнего входа плюс прошедшее время (не дальше 0,5 с), метки не убывают. Если входы молчат, выход — прогноз по модели.

### Логи, метрики, задержка

- `scripts/check_ros.sh` — сборка без сети в `ros:humble-ros-base` с лимитами 2 ядра и 512 МБ, `colcon test` и замер реального времени (`REALTIME_ARGS="--stall-at 30 --stall-s 1.5"` глушит все входы).
- `scripts/realtime_check.py` — синтетические входы с реальной частотой: задержка, частота, разрывы выхода, CPU и память ноды; `--gnss LAT,LON` проверяет выставку.
- `scripts/evaluate_bags.py <прогоны…> --route-map … --stops …` — точность по bag без ROS тем же кодом, что в ноде (нужен pip-пакет `rosbags`).

## 3. Математическая модель

### Модель тяги и торможения (на единицу массы, масса неизвестна)

```
a = f_tr(n, v) − f_br(n, v) − r(v) − g·θ(s) + d

f_tr = (n/15)·min(a_max, a_max·v_base / v),   n > 0     постоянная сила, затем постоянная мощность
f_br = (|n|/15)·b_max·blend(v),               n < 0     blend(v) = 0,8 + 0,2·min(1, v / v_blend)
r(v) = (A + B·v + C·v²)·min(1, v / v_stop)               сопротивление, у остановки плавно к нулю
θ(s) — уклон по высоте карты (база ±10 м)
```

`n` — позиция контроллера −15…15, `v` — скорость, м/с. Параметры (`a_max`, `v_base`, `b_max`, `A`, `B`, `C`) — **стартовые оценки**, их нужно идентифицировать по данным.

### Фильтр вдоль пути (EKF)

Состояние `[s, v, d, k]`: дистанция вдоль пути, м; скорость, м/с; возмущающее ускорение, м/с² (масса, ошибка модели); масштаб колёс, (км/ч тележки)/(м/с).

- **Прогноз** с шагом 0,05 с: `s += v·h + a·h²/2`, `v = max(0, v + a·h)`; `d`, `k` — случайные блуждания. Якобиан по скорости — численно.
- **Измерение** — скорость тележки в км/ч: `h(x) = k·v`, `H = [0, k, 0, 0]`. По колёсам k и v неразделимы, поэтому в этом обновлении k считается известным.
- **Масштаб k** уточняется по привязкам к стоянкам: `k_изм = k · (путь по одометрии) / (расстояние между стоянками по карте)`, при расстоянии ≥ 200 м, не дальше 3 % от k0. Неопределённость k входит в σ_s членом `(σ_k/k · путь после привязки)²`.
- **Стоянка**: обе тележки < 0,1 м/с, нет тяги и оценка < 1 м/с → измерение v = 0. При большей оценке нули колёс — юз, а не стоянка.

### Проскальзывание и отказы датчиков

| Признак | Правило | Действие |
|---|---|---|
| Фаза движения | тяга — медленная тележка, торможение — быстрая, выбег — среднее | выбор скорости для фильтра |
| Расхождение тележек | `|v_f − v_r| > max(0,3 м/с; 3 % v)` два отсчёта подряд | флаг |
| Ускорение колёс | > 2,0 м/с² в тяге, < −3,0 м/с² в торможении (база 0,3 с) | тележка исключается |
| Невязка | χ² > 9 (3σ); флаг после 3 отсечений подряд | отсчёт отбрасывается; дольше 3 с — принимается с большим шумом |
| Зависание | 6 одинаковых ненулевых показаний подряд | тележка исключается до смены показания |
| Пропуск | нет свежих данных > 0,3 с | только модель, ковариация растёт |
| Мусор | NaN, ∞ | отбрасывается |

### Положение

- **Выставка** в окне 5 с: точка старта — медиана фиксов master, если трамвай стоит (одиночный прыжок > 10 м отбрасывается), иначе последний фикс. Курс — по базе антенн master → rover (обе на оси трамвая, 12,436 м): работает и на месте; без rover — по смещению.
- **С картой**: в конце окна s ставится проекцией точки старта на карту с учётом направления (двухпутные участки); дальше координаты, уклон и места стоянок — с карты. **Без карты** — прямая от точки старта. **Без GNSS** — относительная одометрия, `frame_id: odom`.
- **Привязка к стоянке**: стоим > 5 с и ровно одно место стоянки в гейте `3·√(σ_s² + σ_ст²)` (не уже 5 м и не шире 80 м) — поправка s; две стоянки в гейте или ни одной (светофор) — поправки нет.
- **Выходная точка** `base_link` = антенна master + 9,873 м вперёд по пути, высота −3,0 м (tf от организаторов).

## 4. Допущения и параметры

### Допущения

- Проверка идёт по той же линии, что и обучающие прогоны; карту строить по данным разрешено (QA 25.09).
- Трамвай не едет назад. Скорость тележек — в км/ч. Масштаб колёс меняется медленно (износ, группы по прогонам).
- Модель на единицу массы: разница загрузки уходит в возмущение `d`.
- GNSS только в окне выставки; в контуре не участвует.

## 5. Точность и быстродействие

### Точность на синтетике

Сценарий `test/synthetic.py`: 240 с, 1,5 км, цикл «разгон — ход — выбег — торможение — стоянка»; модель фильтра нарочно отличается от «истинной» (тяга на 10 %, тормоз на 8 %), масштаб колёс — на 0,1 %. Наивный счёт — среднее тележек ÷ k, в пропуске держится последняя скорость.

| Сценарий | RMSE скорости, м/с | Ошибка положения в конце, м | Наивный счёт, м |
|---|---|---|---|
| Чистый ход | 0,034 | −0,02 | +2,1 |
| Буксование 25 % (14 с) | 0,130 | +6,8 | +14,9 |
| Пропуск обеих тележек 20 с | 0,088 | +0,7 | +33,5 |
| Юз при торможении | 0,125 | −6,7 | −8,3 |
| Всё сразу | 0,179 | −0,7 | +33,4 |

Масштаб колёс, ошибочный на 0,9 %, и 6 стоянок за 480 с: без привязок ошибка в конце 27 м, с привязками < 2 м, k сходится к истинному с точностью 0,006.

Синтетический rosbag2 (300 с, 2 км, буксование и пропуск тележек, GNSS всю дорогу как эталон) через `evaluate_bags.py`: с тестовой картой — средняя 3D-ошибка 3,6 м, дрейф 0,27 %; без карты — 4,0 м.

### Точность на данных

Не измерена в этой ветке. Команда (нужны датасет, карта и места стоянок):

```bash
pip install rosbags
python3 scripts/evaluate_bags.py <dataset>/data/* --route-map route.csv --stops route_stops.csv --out eval.csv
```

Эталон — `base_link` по двум антеннам в сетке MGRS; сопоставление по метке с допуском 0,05 с. Карту и стоянки для честной оценки нужно строить по другой половине прогонов.

### Быстродействие

`scripts/check_ros.sh` / `realtime_check.py` в `ros:humble-ros-base`, Docker `--cpus=2 --memory=512m --network none`:

| | Без карты, все входы молчат 1,5 с | С картой и GNSS на старте |
|---|---|---|
| Частота `/result/position` | 25,0 Гц | 25,0 Гц |
| Самый длинный разрыв выхода | 51 мс | 79 мс |
| Задержка p50 / p99 / макс. | 24 / 45 / 84 мс | 24 / 45 / 54 мс |
| CPU ноды | 6,2 % одного ядра | 6,5 % |
| Память (RSS) | 59 МБ | 60 МБ |

Сборка без сети и 50 тестов `colcon test` — без ошибок. Требования (задержка ≤ 100 мс, пики ≤ 250, ≥ 10 Гц, ≤ 2 ядер, ≤ 0,5 ГБ, без интернета) выполнены.

## 6. Ограничения и план

### Ограничения

- **Параметры модели не идентифицированы** по данным: без датасета здесь это было невозможно. Возмущение `d` частично компенсирует ошибку модели; при долгих пропусках колёс ошибка будет больше, чем на синтетике.
- **Точность на реальных прогонах не проверена.** Синтетика не воспроизводит реальные шумы, пачки, задержки меток и погоду.
- **Нет отводов у конечных**: старт на пути, которого нет в карте, привяжется к ближайшему пути.
- **Карта и места стоянок** в ветку не входят: их нужно построить по GNSS обучающих прогонов.
- Эталон в оценке — антенны GNSS, у судьи — слияние с лидаром.
- Сообщения `tram_vehicle_msgs` проверены по заменителю с теми же полями.

### План

1. Идентифицировать модель по данным (таблица или параметры `a_max`, `v_base`, `b_max`, сопротивление по выбегу), с кросс-валидацией по прогонам.
2. Построить карту, места стоянок и отводы по половине прогонов и прогнать `evaluate_bags.py` на другой.
3. Подобрать шумы и пороги по результатам: сначала масштаб колёс и гейт стоянок, потом детекторы проскальзывания.
4. Определять номер трамвая по данным: масштаб колёс и отклик на позиции контроллера различаются.
